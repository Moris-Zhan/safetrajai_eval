# 人工審查的結果記為排除清單，不搬移裁切檔案

Re-ID 資料的人工審查結果（某個身分或某張裁切不要用）寫進 `dataset/reid/exclusions.csv`，裁切檔案留在原處；產生資料集版本（manifest）時才套用排除。這和專案既有的「隔離」慣例刻意不同：隔離是把整個專案都不得引用的權重或資料 `mv` 到 `temp/`，排除只影響某一個資料集版本要不要納入。

選擇排除清單而不是搬檔案，有兩個理由：掛載磁碟禁止大量 I/O，審查一次可能涉及大量裁切；同一批裁切需要能依不同的排除清單與規則產生多個資料集版本（例如審查前的 `v1` 與審查後的 `v2`），搬檔案會讓版本之間無法並存、也難以還原。原本的 `quarantine_flagged.py` 會搬移檔案，已改名為 `apply_review_exclusions.py` 並改為只寫排除清單。之後不要為了「看起來比較乾淨」把審查結果改回搬檔案或刪檔案。這項決定由 OpenSpec change `rebuild-reid-dataset` 實作。
