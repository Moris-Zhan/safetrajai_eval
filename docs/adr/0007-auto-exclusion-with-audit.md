# Re-ID 資料以自動排除為主，人工只抽查

Re-ID 資料集版本的品質把關，改為「標記經固定規則產生自動排除，人工只抽查自動排除後剩下的身分」，不再把每個被標記的身分送人工審查。全量資料有約 24,000 個可進版本的身分、3,000 多個被標記的身分，逐一審查約需一個工作天，且會隨來源影片增加。pilot 的 82 個人工審查身分顯示，「靜止身分整段排除、運動跳動整段排除、外觀離群單張排除、四輪與非四輪的類別不一致整段排除」這組規則涵蓋了 95% 的人工排除，約移除 8～10% 的裁切。

我們刻意接受兩種代價：規則會誤排除一部分可用資料（例如停等中的真實車輛、被判為運動跳動的 scooter），以及抽查樣本有限時的殘留風險（每支鏡頭抽 15～60 個，整段串錯的漏網率只能估到約 10～15% 的上限）。誤排除只讓資料變少；漏網則會污染訓練資料，所以規則寧可偏嚴。抽查的不合格率超過 10% 時，要調整該鏡頭或類別的規則並重新抽查，資料量小的鏡頭則直接排除在版本之外。

自動排除與人工排除分成兩份清單，前者可隨規則整份重算，後者只累加；產生資料集版本時兩份都套用。之後不要為了「更保險」改回全量人工審查，而是加大抽查樣本或新增規則。這項決定由 OpenSpec change `auto-reid-exclusions` 實作。

## Considered Options

- **全量人工審查所有被標記的身分與 bus**：品質最直接，但工作量大，且不隨資料量擴展。
- **只自動排除、不做抽查**：最省事，但無法量化規則在其他鏡頭上的效果；規則只以一支序列校準。
- **人與二輪之間的類別不一致也自動排除**：全量中 scooter 被判為 person 的 927 個身分多半是機車騎士造成的誤報，全部排除會多丟約 900 個 scooter 身分；改為先抽樣確認。
