## 兩種分數的說明

- **GS 分數**：grid search 回傳的「排除 0 分序列後取第 25 百分位數」（`core.py:523`），不是平均值。
- **平均準確率**：本報告額外計算的逐序列算術平均（排除無 GT 序列）。
- person／scooter 的 `grid_search_botsort.py` 搜尋網格是沿用舊版針對 ReID 情境設計的範圍，`second_match_thresh`／`unconfirmed_match_thresh` 的候選值跟目前 no-ReID 基準參數不完全重疊，所以這兩類的「GS 分數(基準)」有缺值，只能用平均準確率比較。

## 資料覆蓋度限制

與 ByteTrack 階段相同的 `cctv_all8` 限制：bus 僅 1 段序列有 ROI 內 GT，person 僅 5/6 段，small_truck 僅 4/6 段、truck 僅 3/6 段。bus／small_truck／truck／person 的統計強度弱於 car／scooter，解讀結論時要考量樣本量。

## 最終建議

- **car／small_truck／truck**：採用 grid search 找到的新參數，兩種指標一致顯示改善。
- **bus／person**：維持現狀——bus 樣本量太小（僅 1 段序列），person 這 3 個參數在此資料上完全不敏感（逐序列分數與基準逐位元相同）。
- **scooter**：**不採用**——雖然 GS 分數在其（針對 ReID 設計、範圍受限的）網格內看起來有提升，但用獨立跑出的「最佳參數」驗證結果計算平均準確率後，反而比基準下降（0.7945→0.7815），應維持現狀。
