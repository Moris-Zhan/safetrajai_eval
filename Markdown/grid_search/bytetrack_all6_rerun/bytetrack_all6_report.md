## ⚠️ 兩種分數的差異（務必先讀）

- **Grid Search 分數**：`scripts/grid_search/grid_search_bytetrack.py` 透過 `safetrajai/grid_search/core.py::score_params()` 計算，是「排除 0 分（無 GT）序列後，取各序列 `HOTA.AssA_mean` 的第 25 百分位數」（`core.py` 第 523 行的保守做法，避免極端高分干擾grid search 排名）——**不是平均值**。
- **算術平均準確率**：本報告額外計算的「排除無 GT 序列後的算術平均」，才是使用者要求的「平均準確率」。
- 兩者有時方向相反：person、scooter 在 Grid Search 分數上打平或進步，但算術平均反而下降，代表 grid search 找到的組合犧牲了某些表現較好的序列去換保守指標的穩定——**這種情況不建議採用 grid search 的建議值**。

## 資料覆蓋度限制

`cctv_all8` 只有單一鏡頭（C000025）共 6 段序列，**沒有任何一段同時包含全部 6 個類別**。
ROI 內可評估 GT 統計（6 段合計）：person 234、car 2084、scooter 1324、small_truck 146（4/6 段有）、truck 81（3/6 段有）、**bus 僅 21 個，且全部來自單一段序列**（`152639_15s_2`，`tune` 子集的 4 段序列裡 bus 在 ROI 內的 GT 數量是 0，必須改用 `holdout` 才有訊號）。

bus／truck／small_truck 的統計強度明顯弱於 person／car／scooter，解讀本報告所有結論時要考量樣本量偏小的限制；person 只有 5/6 段序列有可評估 GT，scooter／car 是唯二每段序列都有樣本的類別。

## 最終建議（已更正 grid search 單一分數可能誤導的部分）

- **small_truck**：採用 grid search 找到的新參數（`match_thresh=0.7, second_match_thresh=0.45, unconfirmed_match_thresh=0.85`），兩種指標一致顯示明顯改善。
- **car**：可採用新參數（`0.7/0.5/0.85`），但改善幅度極小（兩指標都 < 0.001），非必要。
- **person／scooter**：**不採用**本次 grid search 找到的參數——保守指標（GS 分數）顯示打平或小幅進步，但算術平均準確率反而下降，代表犧牲了部分序列的表現，維持目前 config 的參數。
- **bus／truck**：維持現狀，這 3 個參數在現有資料上無法區分優劣（樣本量也最小）。
